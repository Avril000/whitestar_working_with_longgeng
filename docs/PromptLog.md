## 第 6 条 · 2026-10-21｜功能：多版本字形自主选择 + 避复

> 这一个功能是**三段对话**长出来的：功能本体 → 自动避复 → 手动避复提示。

### 第一段：功能本体（大意）

| 我输入的片段 | 长庚翻译出来的要求 |
| --- | --- |
| 同一个字在原帖里出现了几十次，写法不一样；希望能自己挑一个版本 | 数据层建 `by_char` 索引，同一字的各版本按碑文出现先后编号；前端加版本切换面板 |
| 同一句里出现重复的字时，不要长得一模一样 | **自动避复**：第 n 次出现的字默认用第 n 种写法（书法忌讳同字雷同） |
| 哪些字有几种写法，界面上要看得出来 | 角标三态：**黄**=没挑 / **黄带晕**=挑了没拍板 / **绿**=拍板了 |

### 第二段：手动避复提示

【全段展示】——这段我自己挺喜欢的，因为它基本就是我说话的样子：先肯定，再联想，最后落到具体怎么用。

> 「长庚，基于你的避复机制，我又想到了一个新的东西。
> 在每个待选字块下面，我们是不是应该加上一句"这个写法已经用了X次"，
> 帮助用户在使用过程中手动避复？」

翻译结果：面板里每个写法下标「本句别处还有几处用了它」，撞了标红并指出是第几个字；
主区域再兜一层底——撞了的格子套朱砂虚线框，状态栏报「N 处同字同形」。

### 第三段：红线补位（长庚自查出来的）

此碑没有某个写法时，**不许拿别的碑的字来凑**——那等于拿颜勤礼碑冒充多宝塔碑。
这条后来写进了无头自检：**48 项**之一。

### 产出

`web/app.js` 重写、`tools/verify_web.js` 自检 48 项全过、`tools/build_manifest.py` 改按版本嵌图。

| 「标红……和另有 1 处已用。这两个文本部分还是蓝色的」 | 第 4 次：版本面板里的**朱砂提示文字**变蓝——这是我自己豁免掉的地方，根治时我判断"面板里没有装饰元素"，**忘了红字也是会被反的** |
| 「其他的你发现了直接修掉吧~」 | 授权我把同类问题一次扫干净，而不是再打一个补丁 |

**根因**：原碑模式是 `filter: invert(1)` **反整张纸**——纸里每加一样新东西，就自动被反一次。
朱砂 `rgb(158,61,50)` 反过去正好是青蓝。

**为什么这次不再打补丁**：前三次我都是给每样装饰"再反一次"抵消掉，
可根子没换，加一样就要补一次，没完没了。

**根治**：原碑模式改成「**纸铺黑 + 字给白**」，不用滤镜——
`background: #0A0B0E` 配 `--ink: #E8E6DE`（字形图是遮罩，颜色由 `--ink` 给）。
观感一样是黑底白字，但纸上的东西一律保持本色，**以后再加什么都不会被污染**。
配套动作：把之前那几条反色补丁**全部删掉**（留着反而会把框重新反成蓝的）；
被标注的格子另给深色底；版本面板同样处理（顺便把黑底的主按钮翻成浅底，否则在黑面板上会消失）。

顺带查出**导出 PNG 里界行、框、印章同样是青蓝的**——导出是 canvas 整幅反色，
他之前看导出时注意力在落款位置上，没留意颜色。
修：把界行、借字框、版框、印章抽成 `paintDecor()` / `paintSeal()`，**排在反色之后补画**。

> 这条我自己的教训最重：**"整幅滤镜"是设计债**。
> 它省事一次，之后每加一个元素都要付一次利息。
> 想让某个东西变样，就去改它的**属性**（背景、颜色），别用覆盖全体的滤镜。
> 另外：做"根治"时要回头扫一遍**自己豁免掉的地方**——
> 我写下"面板里没有装饰元素"就把面板排除了，可"装饰"不只线条，红字也是。

产出：`web/style.css`、`web/app.js`（`paintDecor` / `paintSeal`）；自检 151 → 153 项

**查到了什么**：北大古文献研究所《古籍版式》——「界行，版框内每行字之间的分界线」；
以及「古代行文，上下竖写，由右及左」。两句话合起来推出一条规则：
**界行是行与行之间的分界线，它的方向必然与字的走向垂直**——
竖排成列就只能配竖线，横线只能配横排。
另有一本集字字帖写得更直白：「由上到下安排字距，由右到左安排行距」（正好和我们滑杆的命名一致）。

⇒ **他的直觉是对的**。以前那个"竖排 + 在每个字下方画横线"，
等于把横排的界行硬套在竖排上，根本不成立。

**改**：把"方向"从界行的子选项升格为**排列方向**（关掉界行也能选）——
竖排 = 字从上到下成列、列序从右到左；横排 = 字从右到左成行、行序从上到下。
界行线自动跟着方向走，两个方向都贯穿整幅。
实现上 `strip` 一行没改，只把每段内部改成"横着排、从右往左"。
顺带把语义理顺了：`--gg` 永远是字与字，`--gr` 永远是列与列 / 行与行，两个方向都成立。

## 附：这几遍梳理下来，我自己看见的四件事

回头看这些对话，有几个我以前没留意的习惯：

1. **我会给 AI 举例子。** 很少直接说"做个某某功能"，更多是描述一个具体的、看得见的场景——
   例子比形容词管用得多。
2. **我说话是带情绪的**（"巨大的进步！""齐活了""辛苦了"）。
   起初以为这是闲笔，后来发现它在传递判断：我高兴，说明这回对了；我含糊，说明这里有事。
3. **最容易漏讲的，恰恰是我以为"我们已经很有默契"的那部分。**
   真要落成文字才发现——我根本没讲清楚过。
4. **一个功能一个功能地做，是有道理的。**
   一次只做一件小事，既容易实现，也能提前发现潜在的问题——
   尽管 debug 很头疼，但总比所有 bug 一起冒出来、再慌慌张张地找是哪一步出的问题要好修得多。
   这条不只适用于 AI Coding，以后做别的项目也是一样。
