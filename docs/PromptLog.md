## 第 3 条 · 2026-10-16（晚）

### 我们如何提问

> 同步两条附加信息：① 汇报可自带电脑，展示环境以本机为准；② 班级有一台共享服务器（附服主发的使用文档）。
> 就服务器提出三个问题：**要不要用？什么时候用？怎么用？** 并说明全组都不会用服务器，交由长庚判断。

### AI 给了什么

- 指出文档中的一个**高风险误读**：教学步骤让大家 `cd /home/ubuntu/guji-jiaocuo` 后改 `app.html`，但那是古籍系统（服主项目）的目录，全班照做会互相覆盖、改坏系统。正确做法是 mkdir 自己的文件夹
- 服务器判断：**用，但走「双轨制」** —— 本地版是主轨（保命），服务器在线版是副轨（加分，打不开立刻切本地）
- 五条风险清单：共享账号密码 / 端口依赖服主手动放行 / 稳定性未知 / 教室网络未必通 / 进程可能悄悄挂掉
- 三种用法按价值排序：在线展示（推荐）> 团队环境（可选）> 跑抓取（待评估）
- 时间线：W1 只做一件事——找服主要端口；W2 末才部署；11/04 彩排双轨各跑一遍
- 三条安全红线：密码不进 GitHub / 不碰别人目录 / 服务器不是备份
- 结论：**这两条信息反而强化了方案 C** —— 纯静态产物一份两用（本地双击 + 服务器部署零改动），而 Flask 方案要维护两套

### 我们如何核验 / 修订

- 申请端口建议 **5019**（对应课题 19，好记、不易冲突），备选 5119 / 5219
- 待白星决定：是否授权长庚直接连服务器（长庚建议第一阶段先不连，由队友练手 SSH，出错把报错原文贴回）
- 待办：找服主申请端口放行；确认密码保管方式（不进仓库）

### 产出文件

### 我们如何提问

> 组会拍板结果写进 02 与 03。决议要点：

> B1 做成**两个按钮**（底本 + 排版）；B2 历史集字 = 用户自己的记录；
> C1 数据按**记录数**计；C2 笔顺教程**暂时舍弃**；C3 共同工作、**任务拆小下发**。
> 数据源实测：中华珍宝馆（主力）/ 书格、维基共享（备选）/ 故宫、古籍库（排除）。
> 要求：**继续推进**。

### AI 给了什么

- 数据源结论：**三可用两排除**，并提炼出馆方那条关键规矩——**标来源要标馆藏机构，不标本站**
- **W2 任务清单**（T0–T22 共 23 个小任务，按数据/工程/文档/共通分组，全部可认领）
- **前端 MVP 骨架**：`web/index.html` + `style.css` + `app.js`
- **元数据模板** `data/metadata/glyphs.json` + 转换脚本 `tools/build_manifest.py`
- PDF 渲染脚本 `tools/pdf_to_pages.py`

### 我们如何核验 / 修订

- **避开一个真实陷阱**：本地双击打开网页时，浏览器安全策略会拒绝读取 JSON。
  所以数据走「JSON（人读）→ 脚本 → data.js（网页读）」，**双击即可运行，无需起服务器**
- **缺字不渲染假字**：缺字时只留空位并标「缺」，绝不用系统字体冒充碑帖字形——这是课题红线，在 MVP 阶段就做对
- 三种字状态在 MVP 全部可见：原帖字（黑）/ 借来的字（朱砂虚线+角标+悬停）/ 缺字（留空）
- 切字脚本（`crop_glyphs.py`）**暂不交付**：切字算法必须对着真实页图调，凭空写大概率不好使。等拿到真实 PDF 再写
- 自检：构建脚本跑通，app.js / data.js 语法校验通过
