## 第 1 条 · 2026-10-15（傍晚）

### 我们如何提问

> 给出课题说明文件（21 个课题 + 三层评分标准），明确提出：**先不启动任何工程**，先梳理使用 AI 开发的大致流程——需要准备什么？有几个环节？每个环节我们要提供什么、AI 会给什么、我们需要处理什么？

### AI 给了什么

- 六环节流程图：准备 / 定义 / 设计 / 建造 / 验证 / 交付
- 每环节三方契约（你们给我 / 长庚给你们 / 只能你们判断）
- 五条反直觉常识：描述要具体、报错丢原文、一次一个功能、AI 会编须人工核验、跑通即存档
- 一份可分享给队友的《AI 协作开发手册》

### 我们如何核验 / 修订

- 白星确认流程划分符合小组实际情况 → 采纳
- 结合课题补充：把「文化准确性人工核验」单列为不可外包的判断项（课题反复强调核对状态与不允许冒充）
- 产出：《AI协作开发手册.html》

## 第 2 条 · 2026-10-15（晚）

### 我们如何提问

> 队长交接：汇报日 11/05，目标冲挑战层；队伍 5 人，本周任务为环境自查 / 功能脑暴 / 学 Git；
> 提出四项诉求：① 划定长庚与仓库的边界（不直接访问桌面仓库）；② 协作形式为线下聚活或线上共创；
> ③ 前后端选型请给推荐；④ 数据尽量采用老师给出的参考网址。要求先完善骨架信息。

### AI 给了什么

- 技术选型方案 C：**构建期 Python（加工厂）+ 运行期纯前端（成品）**，含三方案对比、理由、具体技术栈、算法清单、界面调性
- 项目骨架：完整目录结构 + README + .gitignore
- 五人分工矩阵 + 8 条 Git 协作规则 + 两种协作模式的配合方式
- 三周时间线（含检查点与风险降级预案）
- 数据源初步评估（11 个站点按集字价值分级）+ 实测清单 + 底本碑帖候选

### 我们如何核验 / 修订

- **边界约定**：长庚工作副本与仓库同构但物理隔离，产出经白星审核后同步 —— 已写入协作规范，全体成员可见
- **未实测声明**：数据源评估为初步判断，**未联网实测**（当前网络受限，长庚不擅自启用代理），实测任务交由小组成员分头完成
- **待拍板项**：方案 C 是否采纳 / 底本碑帖选哪 1–2 种 / 是否接受"管线 + 数量"双达标打法

`README.md`、`.gitignore`、`docs/00-项目概览.md`、`docs/01-技术选型.md`、`docs/02-需求清单.md`、`docs/03-数据源调研.md`、`docs/04-分工与协作规范.md`、`docs/05-时间线与里程碑.md`
