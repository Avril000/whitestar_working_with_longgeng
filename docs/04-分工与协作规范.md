# 04 · 分工与协作规范

## 一、五人分工建议

> 白星为队长。以下为建议矩阵，可按各人兴趣调整；**关键是每项都有唯一负责人**。

| 角色 | 人数 | 具体职责 | 产出物 |
| --- | --- | --- | --- |
| **队长**（白星） | 1 | 需求敲定、进度把控、与长庚对接、审核并同步所有产出、上台汇报 | 决策、同步、汇报 |
| **数据与考据** | 2 | 找碑帖图像、下载、核出处（碑名/年代/收藏地）、标核对状态、整理底本背景资料 | `data/`、核对表 |
| **工程与界面** | 1 | 与长庚一起写代码、调 CSS、做排版与导出、本地跑通验证 | `web/`、`tools/` |
| **文档与汇报** | 1 | Prompt Log、迭代截图、分工说明、PPT 制作、论文素材收集 | `docs/`、`presentation/` |

### 分工原则

- **按兴趣和投入时间分，不按"谁强"硬分。** 课程要的是过程，不是结果最优。
- **每个人都必须留下可查证的产出**（提交记录、文档署名、截图），这是分工说明的依据。
- **数据与考据是本项目最重的活**（字形库全靠人工核），给 2 人是合理的，不要砍。

## 二、Git 协作规则（新手版，务必遵守）

> 5 个人同时提交，最怕两件事：冲突、覆盖。下面 8 条就是为这个定的。

1. **只用一个分支（main），谁都不许开新分支。** 分支是进阶技能，新手开分支必乱。
2. **开工前先 `git pull`，提交前再 `git pull` 一次。** 养成肌肉记忆。
3. **只在自己负责的目录里改文件。** 数据组只动 `data/`，工程组只动 `web/` `tools/`，文档组只动 `docs/` `presentation/`。**绝不改别人的文件。**
4. **需要共同编辑的文件（如需求清单），先在群里或在线文档里讨论定稿，再由一个人提交。** 不要两人同时改同一个 md。
5. **提交信息写清楚是谁、做了什么**，格式：`[名字] 做了什么`，例：`[张三] 补充九成宫字形 30 条`。
6. **大文件不进仓库。** 高清原图、PDF 放到 `data/raw/`，已在 `.gitignore` 里排除。
7. **遇到冲突不许 `push --force`。** 把报错原文整段发给白星或长庚，我们来处理。
8. **每天结束前推一次**，别攒三天再推——攒得越久，冲突越难解。

### 遇到 Git 报错怎么办

- 把**红字原文完整复制**下来（不要转述、不要只截半句）
- 发给白星，或直接贴给长庚
- 什么时候做的什么操作、报错前的最后一步是什么，一并说明

## 三、两种协作模式怎么配合

### 聚在一起组活（适合需要"人"的判断的事）

- 需求脑暴、砍需求
- **字形出处的核对**（这是最需要一起看的活，两个人互相复核一遍，准确率翻倍）
- 版本验收：一起看这一版行不行、够不够好
- 汇报演练：计时、挑刺

### 线上分开做（适合能独立推进的事）

- 下载素材、整理元数据
- 写文档、做 PPT
- 跑构建脚本
- 学 Git、学环境

### 关于代码

**代码由"长庚主笔 + 工程负责人配合"产出，不由 5 人同时改动。**

理由很实在：5 个新手同时改代码，冲突会大到无法收拾。正确姿势是——
大家把意见提给工程负责人，由他和长庚一起落地。这样既保证每个人都有参与，又不会把仓库搞崩。

> 如果有人想自己动手写，欢迎——在 `web/` 或 `tools/` 下新建自己的文件练手，不改动主干文件。

## 四、长庚的工作边界（本项目特别约定）

> 这是白星作为队长对团队负责的要求，长庚完全接受并严格遵守。

| 约定 | 说明 |
| --- | --- |
| **长庚不直接访问桌面仓库** | `D:\桌面\whitestar_working_with_longgeng\` 下的文件，长庚**不读、不写、不扫、不改** |
| **长庚的工作副本** | 位于 Work Buddy 工作区，与仓库**目录结构完全一致**，方便一一对应同步 |
| **同步由白星执行** | 长庚每次产出附一份「同步清单」（新增/修改文件 + 建议的 commit message），白星审核后再同步进仓库 |
| **唯一例外** | 若需要排查仓库里的问题，由白星**主动把文件内容贴给长庚**，长庚只看贴过来的内容 |

### 为什么这样定

队友把信任交给队长，队长就要对每一份进仓库的内容负责。**先审后入**，是对团队最好的保护。

## 五、沟通约定

- 群里同步进度，每 2–3 天一次简短汇报（做了什么 / 卡在哪 / 下一步）
- 所有与长庚的关键对话，由文档负责人整理进 `docs/PromptLog.md`
- 有疑问立刻问，不留模糊——包括问长庚
