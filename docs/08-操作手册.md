## 〇、先回答那个小问题：`.py` 能双击吗？

**不能，也别试。**

三个原因，都很实际：

1. **没装关联**。`.py` 在你机器上默认没有"双击=运行"的关联，双击出来的是"选择打开方式"对话框。
2. **窗口会一闪而过**。就算跑起来了，程序跑完窗口立刻关掉——**你根本来不及看它报了什么错**。出了问题你只会看到黑框闪了一下，然后什么都没有。
3. **可能用到错的 Python**。我给你的脚本要用到 `pillow / numpy / scipy` 三个包，它们装在**隔离环境**里（`C:\Users\BOHAN LYU\.workbuddy\binaries\python\envs\default`）。双击时系统可能用另一个干净的 Python，直接报 `ModuleNotFoundError`。

所以我做了四个 `.bat`。**`.bat` 双击就是运行**，而且我让它跑完停住等你按键——不会闪退。

## 一、四个双击入口（放在项目根目录）

## 二、完整流程：一张图 → 组员的包

```
 ①你把页图丢进去        ②双击一个 bat          ③发给组员
 ┌──────────────┐      ┌──────────────┐     ┌──────────────┐
 │ data/processed │  →   │ 一键_出卡片包  │  →  │ dist/xxx.zip │
 │   01.png      │      │              │     │              │
 │   02.png      │      │  （中间全自动）│     │ 微信/QQ 传过去 │
 └──────────────┘      └──────────────┘     └──────────────┘
```

### 第 1 步：把页图放进 `data/processed/`

- 文件名必须是 **`01.png`、`02.png`、`03.png`** 这样——数字 + `.png`
- 数字就是我们的"页序号"，后面所有文件名都靠它串起来
- 图从哪来：中华珍宝馆截图 / PDF 转出来的页图（`tools/pdf_to_pages.py`）

> ⚠️ **页序号 ≠ 珍宝馆图号。** 珍宝馆图片是倒着排的，
> 我们的 `01.png` 对应珍宝馆图号 **34**。这个对应关系在 `data/pages_info.json` 里，
> 卡片的"珍宝馆图号"列就是从这儿取的。**换页了记得改这个文件**，不然出处全错。

### 第 2 步：双击 `一键_出卡片包.bat`

它会依次干这几件事，全程有中文提示：

| 顺序 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 二值化、去朱红印章、列投影+连通域切字 | `glyphs_XX/crop/` 下的小图 |
| 2 | 拼一张带序号的总览网格图 | `glyphs_XX/card_sheet.png` |
| 3 | 生成 csv 卡片（一页一张） | `data/cards/卡片_XX页.csv` |
| 4 | 收进一个文件夹并压缩 | `dist/卡片包_日期.zip` |

**已经切过的页会自动跳过**（提示"已有 N 个字块，跳过切字"），不会覆盖你手工补的块。放心反复双击。

跑完窗口会停在 `Done. Send the zip in dist\ to your group.`，看一眼有没有红色报错再关。

### 关于两种页图、两种切法

| 页图长什么样 | 模式 | 用哪个脚本 | 怎么标 |
| --- | --- | --- | --- |
| 整幅碑文，竖排一长列一长列 | `column`（默认） | `crop_glyphs.py` | 不用标，默认就是 |
| **珍宝馆「单字临摹」页**：一格一字，已排成网格 | `grid` | `crop_grid.py` | 在 `data/pages_info.json` 里给该页写 `"mode": "grid"` |

**网格模式切得又快又准**：04 页自动量出 3 行 × 10 列，一刀切出 30 个字，一个不多一个不少，
还顺手去掉了格子边框。比整幅碑文那种"靠算法猜字在哪"的方式干净太多。

网格页的阅读顺序可以在 `pages_info.json` 里写 `"order"`：

- `"row"`（当前默认）：从左到右、从上到下
- `"col"`：传统竖排，最右一列优先，列内从上到下

> ⚠️ **这个顺序必须你亲自看一眼 `04页_字块总览.png` 确认。**
> 顺序错了，后面所有"碑文第 N 字"的推断就全错。不对就改 `pages_info.json`，
> 再双击「强制重切.bat」重切一遍，几秒钟的事。

### 单字临摹页的标准作业流程（2026-10-20 定稿）

珍宝馆的「单字临摹」列表**按碑文顺序排列，每个字下面有电子版标注**，但不能下载、只能截图。
所以流程是：

```
白星：滚动页面，连续截图（相邻两张要有一点重叠）
  → 把截图按 05.png / 06.png 放进 data/processed/
  → 双击「一键_出卡片包.bat」（网格模式自动切字）
  → 长庚读截图里的标注，把字预填进卡片
  → 组员只需「核对」，不用认字
```

- **截图重叠很重要**：列表是滚动的，相邻截图有重叠部分，长庚靠重叠处的字对齐拼接、自动去重。
- **不用下载图片**：截图里的字图 + 标注已经足够整条流水线运转。

### 按人分活：一人一份卡片

卡片是按"截图"生成的（一张 200 字），但干活的是人。用这个按人数重新切：

```bash
python tools/split_cards.py --parts 4 --prefilled   # 均分 4 份
python tools/split_cards.py --per 250 --prefilled   # 每份 250 条
```

- `--prefilled`：只分**已预填字、只需核对**的条目；整幅碑文那批（还没认字的）不混进来，
  因为那是两种完全不同的活
- 输出在 `data/cards/分组/卡片_第1组.csv …… 第N组.csv`，一人发一个
- 打印里会给出每组的字号范围（碑文第几字 → 第几字）

组员要看的说明在 `data/cards/分组/核对任务.md`，可直接转发。

### 更快的一招：释文整页复制，程序自动对号入座

珍宝馆单字临摹页上的字**能整页复制成文本**（Ctrl+A → Ctrl+C → 粘进 txt）。
既然有文本，就不用人眼认小字了——按序号一一对应，准确率 100%。

1. 在页面上 `Ctrl+A` → `Ctrl+C`，粘进一个 txt，存到桌面
2. 长庚把释文存进 `data/metadata/多宝塔碑_释文.txt`（去掉开头「搜索单字/搜索」这类界面文字）
3. 跑一次对号入座：

```bash
python tools/apply_text.py 05 --start 1      # 这一页从碑文第 1 字开始
python tools/apply_text.py 06 --start 201    # 下一张从第 201 字开始
```

卡片里的「字」和「出处位置（碑文第 N 字）」会被**全部预填**，
组员只剩一格要动：**核对人**。

> 本次实测：《多宝塔碑》释文 **2024 字**，一页不差。
> 现在 `查12字缺口.bat` 还会直接告诉你每个目标字**在碑文第几字、需要截第几张图**。

### 长图到底能截多长（2026-10-20 实测）

**能用，而且越长越划算。** `05.png` 实测：2158 × 6011，一次切出 **20 行 × 10 列 = 200 个字**，
笔画占比 0.11~0.34、无残缺无空格，质量和单页截图一模一样。

| 项目 | 建议值 |
| --- | --- |
| 一次截多少 | **15~25 行**（约 150~250 字），图高 **6000~9000 px** |
| 本次 05.png | 6011 px / 20 行 / 200 字 —— **正好是推荐尺寸** |
| 硬上限 | 图高别超 **25000 px**（再大内存和打开都吃力） |
| 相邻两张 | **重叠约 1 行**（往下滚之前往回退一点），边界行切坏了也不丢字 |

两个保护机制已经写进程序：

1. **残缺行自动丢弃**：首尾只截到一半的行会被识别并丢掉，不会混进半个字。
   05.png 就自动丢了 2 行（顶部浏览器白边 + 底部截半的行）。
2. **顶部/底部白边不算行**：滚动截图常带的浏览器白边不会被当成字。

> 想验证一张长图切得好不好，看跑完的输出：
> 「丢弃残缺行 N 行」是正常提示；如果最终字数 ≠ 行数 × 10，说明有格子是空的，值得看一眼总览图。流水线运转。
- **搜索框可以直接用**：珍宝馆这页有「搜索单字」框，演示要用的 12 个字
  （注意用繁体检：江 山 如**畫** 厚 德 **載** 物 **寧靜** 致 **遠**）可以逐个搜，几分钟集齐。

## 三、收回来：组员交了卡片之后

### 第 1 步：把三张 csv 放回 `data/cards/`

- **同名覆盖**原来的文件（`卡片_01页.csv` 覆盖 `卡片_01页.csv`）
- **不要改名**，不要留成 `卡片_01页(1).csv` 这种

### 第 2 步：双击 `一键_收卡片.bat`

它做四件事：

1. **回填**：把 csv 里填的字、出处位置、核对人、备注写进字形库
   - 字和核对人都填了 → 状态「已核对」
   - 备注里写了"存疑" → 状态「存疑」
   - 字没填 → 保持「未核对」，不入库
2. **翻墨**：把拓片单字（黑底白字）转成网页用的透明底墨字图
3. **生成网页数据**：`web/data.js`（字形图按字去重后嵌入，双击就能跑）
4. **报缺口**：直接告诉你 12 个字齐了没

### 第 3 步：双击 `web/index.html` 看效果

不用起服务器、断网也能开。这就是汇报那天要演示的东西。

网页上能做的：

| 操作 | 说明 |
| --- | --- |
| 输入一句话 | 实时用**真拓本字形**拼出作品 |
| 对联 | 点「条幅」切换；输入时**用空格分隔上下联**，右列为上联 |
| 切碑帖 | 点「多宝塔碑」按钮（颜勤礼碑取完字后自动可用） |
| 悬停任意字 | 显示出处位置、核对状态、核对人 |
| 缺字 | 如实留空 + 虚线框，**绝不显示假字**（红线） |
| 历史集字 | 右上角按钮；每次导出 PNG 会自动留档，可一键恢复 |
| 导出 PNG | 拓本墨字 + 界格 + 落款 + 朱砂印章，直接交作业 |

## 六、出错了怎么办

| 你看到的 | 意思 | 怎么办 |
| --- | --- | --- |
| `[ERROR] Python environment is not ready` | 隔离环境的 Python 找不到了 | 找长庚 |
| `[停] 找不到页图：04.png` | `data/processed/` 里没这个文件 | 检查文件名是不是 `04.png` |
| `[停] data/processed/ 里没有 01.png 这样的页图` | 一张页图都没有 | 先放页图 |
| `ModuleNotFoundError: PIL` | 用错 Python 了 | 别双击 `.py`，双击 `.bat` |
| 卡片条数比上次少很多 | 可能某页被重切坏了 | 去 `glyphs_XX/_stale/` 翻旧结果 |
| 组员填的字没进库 | 名字写错列 / 存成了 xlsx | 看 `一键_收卡片` 输出的"已填 N 条" |

**万一切坏了别慌**：`强制重切.bat` 每次都会把旧结果先挪到 `glyphs_XX/_stale/时间戳/`，
从不直接删。想找回哪个文件，从那儿拷回来就行。

## 八、这套东西为什么这么设计（给你讲透，汇报时可能用得上）

**为什么不干脆做个网页上传图片、一键切字？**
能做，但要服务器、要上传、要处理跨域。我们 11/05 就要汇报，把工程量花在演示效果上更划算。
切字是**组会时在你自己电脑上跑一次**的事，不需要做成产品功能。

**为什么卡片用 csv 而不是在线表格？**
csv 是纯文本：能进 git、能版本对比、程序零误差读回来、Excel 双击就能填。
在线表格要联网、要权限、导出格式还容易变。

**为什么切完还要"人工核对"这一道？**
拓本字口模糊，机器只能定位"这里有个字"，认不出"这是什么字"。
而且**认错字是硬伤**——汇报时老师指着一个错字问"这是颜体的'德'吗"，
比留个空格难看得多。所以我们的红线是：**库里有就必须有出处、有核对人、有状态。**

**为什么"存疑"要单独一个状态？**
因为我们不确定的东西要**敢说不确定**。网页上会显示黄色角标，
老师问起来你能坦然说"这个字风化严重，我们标了存疑"——这是加分项，不是扣分项。
