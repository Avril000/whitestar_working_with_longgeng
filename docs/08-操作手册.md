## 〇、先回答那个小问题：`.py` 能双击吗？

**不能，也别试。**

三个原因，都很实际：

1. **没装关联**。`.py` 在你机器上默认没有"双击=运行"的关联，双击出来的是"选择打开方式"对话框。
2. **窗口会一闪而过**。就算跑起来了，程序跑完窗口立刻关掉——**你根本来不及看它报了什么错**。出了问题你只会看到黑框闪了一下，然后什么都没有。
3. **可能用到错的 Python**。我给你的脚本要用到 `pillow / numpy / scipy` 三个包，它们装在**隔离环境**里（`C:\Users\BOHAN LYU\.workbuddy\binaries\python\envs\default`）。双击时系统可能用另一个干净的 Python，直接报 `ModuleNotFoundError`。

所以我做了几个 `.bat`。**`.bat` 双击就是运行**，而且我让它跑完停住等你按键——不会闪退。

## 二、新管线（推荐）：投递箱制卡

### 为什么换了这套

老管线是全量扫 `data/processed/`，**所有碑、所有页混在一起**。页一多就踩了两个坑：

1. 两块碑的碑文字号**都从 1 开始**，按字号去重直接撞车（1458 条颜勤礼碑的字全被记成多宝塔碑）。
2. 每加一块碑都要我手动登记 `pages_info.json`，你没法自己加碑。

新规矩：**这一轮要做什么，就往 `data/inbox/` 放什么**。向导只碰投递箱里的东西，
做完自动挪进 `_已处理_日期/` 归档，永不和历史数据混在一起。**加第三块碑你自己就能做完。**

### 四步走

```
 ①往投递箱放东西        ②双击向导答题          ③程序自动跑完        ④发给组员
 ┌──────────────┐     ┌──────────────┐     ┌──────────────┐   ┌──────────────┐
 │ data/inbox/  │  →  │ 一键_投递制卡  │  →  │ dist/卡片包_  │ → │ 微信/QQ 传过去 │
 │  y01.png …   │     │  （问答式）   │     │ 第XX页_日期.zip│   │              │
 └──────────────┘     └──────────────┘     └──────────────┘   └──────────────┘
```

**第 1 步 · 往 `data/inbox/` 放**：

| 放什么 | 命名 | 说明 |
| --- | --- | --- |
| 页面截图（必需） | `y01.png` `y02.png` … | 珍宝馆「单字临摹」页的滚动长图，一页一张。**文件名就是页码**，向导按名字排序处理 |
| 碑文释文 txt（**只有新碑需要**） | `颜勤礼碑_释文.txt` | 已有碑不用放，向导自己会去找 |

**第 2 步 · 双击 `一键_投递制卡.bat`**，它会问你这几件事（回车 = 用默认值）：

1. **这批图属于哪块碑** —— 列已有的碑让你选；选「新碑」才要补下面的信息
2. 新碑才问：珍宝馆链接、馆藏机构、释文 txt 在哪（**可以把文件直接拖进窗口**）
3. **这批第一格对应碑文第几字** —— 接着上一批做就填"上一批最后一个字 + 1"，全新一批直接回车（=1）
4. **相邻两张截图重叠几个字** —— 默认 10，直接回车就行
5. **看图核对锚点** —— ⭐ **这是整条管线里唯一留给人的判断**，见下

**第 3 步 · 程序自动跑完**：切字 → 制卡 → 打包 → 清空投递箱（原图归档到 `_已处理_日期/`）。

**第 4 步 · 把 `dist/卡片包_第XX页_日期.zip` 发给组员**。

### 关于锚点查验（别跳过）

切完字会**自动弹出一张查验图**：每页的头三块、尾三块，旁边标着"按推算它应该是碑文第 N 字"。
**你扫一眼对不对就行**——程序不知道切出来的字和释文对不对得上，人一眼就知道。

- 全都对得上 → 直接回车
- 有页不对 → 输入页名（空格分隔），它会问你"首块是 G 几""对应碑文第几字"，
  改完**后面所有页自动按新起点重新顺推**，并再弹一张新查验图给你复核

> 这一步省掉，后面几千条字的出处全错，而且错得很隐蔽。**值得花那 30 秒。**

### 长图到底能截多长（实测）

**能用，而且越长越划算。** 实测 2158 × 6011 的图，一次切出 **20 行 × 10 列 = 200 个字**，
笔画占比 0.11~0.34、无残缺无空格，质量和单页截图一模一样。

| 项目 | 建议值 |
| --- | --- |
| 一次截多少 | **15~25 行**（约 150~250 字），图高 **6000~9000 px** |
| 硬上限 | 图高别超 **25000 px**（再大内存和打开都吃力） |
| 相邻两张 | **重叠约 1 行**（往下滚之前往回退一点），边界行切坏了也不丢字 |

两个保护机制已经写进程序：

1. **残缺行自动丢弃**：首尾只截到一半的行会被识别并丢掉，不会混进半个字。
2. **顶部/底部白边不算行**：滚动截图常带的浏览器白边不会被当成字。

> 想验证一张长图切得好不好，看跑完的输出：
> 「丢弃残缺行 N 行」是正常提示；**如果最终字数 ≠ 行数 × 10，说明有格子是空的**，
> 值得打开总览图看一眼。

## 三、老管线（备用）：`一键_出卡片包.bat`

新碑、新批次一律走投递箱。老入口留着是为了**对已有页图重出一次包**，流程是：

| 顺序 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 二值化、去朱红印章、切字 | `data/processed/glyphs_XX/crop/` 下的小图 |
| 2 | 拼一张带序号的总览网格图 | `glyphs_XX/card_sheet.png` |
| 3 | 生成 csv 卡片（一页一张） | `data/cards/卡片_XX页.csv` |
| 4 | 收进一个文件夹并压缩 | `dist/卡片包_日期.zip` |

**已经切过的页会自动跳过**（提示"已有 N 个字块，跳过切字"），不会覆盖你手工补的块。放心反复双击。

### 两种页图、两种切法

| 页图长什么样 | 模式 | 用哪个脚本 | 怎么标 |
| --- | --- | --- | --- |
| 整幅碑文，竖排一长列一长列 | `column`（默认） | `crop_glyphs.py` | 不用标，默认就是 |
| **珍宝馆「单字临摹」页**：一格一字，已排成网格 | `grid` | `crop_grid.py` | 在 `data/pages_info.json` 里给该页写 `"mode": "grid"` |

网格页的阅读顺序可以在 `pages_info.json` 里写 `"order"`：

- `"row"`（默认）：从左到右、从上到下
- `"col"`：传统竖排，最右一列优先，列内从上到下

> ⚠️ **这个顺序必须你亲自看一眼总览图确认。** 顺序错了，后面所有"碑文第 N 字"的推断就全错。

### 按人分活：一人一份卡片

```bash
# 或者双击「一键_分组.bat」，它会问你分几份
python tools/split_cards.py --parts 4 --prefilled   # 均分 4 份
python tools/split_cards.py --per 250 --prefilled   # 每份 250 条
```

- `--prefilled`：只分**已预填字、只需核对**的条目；整幅碑文那批（还没认字的）不混进来，
  因为那是两种完全不同的活
- 输出在 `data/cards/分组/卡片_第N组.csv`，一人发一个
- 组员要看的说明在 `data/cards/分组/核对任务.md`，可直接转发

## 四、收回来：组员交了卡片之后

> 🚨 **这一节的三条规矩是硬规矩**（2026-10-26 立，都是踩过坑才立的），别图省事跳步。

### 第 1 步：把 csv 放进 `data/cards/回收/`（**只认这一个文件夹**）

| 做 | 不做 |
| --- | --- |
| ✅ 收回来的卡片放进 **`data/cards/回收/`** | ❌ 别往 `data/cards/` 根目录一丢了事 |
| ✅ **同名覆盖**（`卡片_y01页.csv` 覆盖同名文件） | ❌ 别留成 `卡片_y01页(1).csv` |
| ✅ 存成了 `.xlsx` 就让组员另存为 CSV | ❌ 别直接丢 xlsx 进去 |

> 为什么这么死板：`cards/` 根目录下堆着**历史卡片、旧分组件、抽样件**。
> 扫整个目录会把**没人核对过的脏数据**一起读进库——2026-10-26 就多混了 41 条，
> 全是"未核对"，还和已入库的字撞了 39 组。
> **制卡发到 `dist/_pack_XX`，收回来的放进 `data/cards/回收/`，两处对称。**

### 第 2 步：双击 `一键_收卡片.bat`

它做四件事：

1. **回填**（`merge_cards.py`）—— 进库要过**三道关**，少一道都不收：
   ① 有字；② 没被弃（备注/出处栏没写 `【弃】`）；③ **有人签过字**（核对人是必填栏）
   - 没签字的宁可留空，也别放进库
   - 备注里写了「存疑」→ 状态「存疑」，网页上显示黄色角标
2. **翻墨**（`make_webglyphs.py`）—— 拓片是黑底白字，不过这一步在网页上就是**黑方块**。⚠️ 不可省
3. **生成网页数据**（`build_manifest.py`）→ `web/data.js`（字形图按版本 base64 嵌入，双击就能跑）
4. **报缺口**（`check_goals.py`）

### 关于"字形库"的两个坑（改数据前必看）

- 🚨 **`data/metadata/glyphs.json` 不是真身，逐页 `meta_*.json` 才是**。
  汇总每次**全量重建**——所以**要回滚必须回滚 meta 那一层**，只回滚 `glyphs.json` 没用，
  重新汇总脏数据又会长回来。
- ⚠️ **增量合并删不掉东西**：一条记录进过库就赖着不走，被弃、被清空也一样。
  要清干净，去 meta 里改。

### 第 3 步：双击 `web/index.html` 看效果

不用起服务器、断网也能开。这就是汇报那天要演示的东西。

| 操作 | 说明 |
| --- | --- |
| 输入一句话 | 实时用**真拓本字形**拼出作品 |
| 长句子 | 点输入框右边的「放大」，输入框就地展开成一块高编辑区，可滚动；再点还原 |
| 对联 | 点「条幅」切换；输入时用**空格或换行**分隔上下联，右列为上联 |
| 字数 | 输入框下面报「共 N 字」；超过 150 字会标红提醒——再长导出会超出浏览器画布上限 |
| 切碑帖 | 两块碑自由切换（第三块碑入库后自动长出来，前端不用改一行） |
| **集字调整**抽屉 | 六项：样式 / 成册 / 间距 / 遮罩 / **朱笔** / **借字** |
| **借字**（第六项） | 三档：**不借**（默认，红线）/ **补缺**（只补本碑没有的）/ **混搭**（把别碑写法也列出来挑） |
| 悬停任意字 | 显示出处位置、核对状态、核对人 |
| 缺字 | 如实留空 + 虚线框，**绝不显示假字**（红线） |
| 历史集字 | 右上角按钮；每次导出 PNG 会自动留档，可一键恢复 |
| 导出 PNG | 拓本墨字 + 界格 + 落款 + 朱砂印章，直接交作业 |

> **关于借字的两条底线**（2026-10-27 定）
> ① 默认**不借**——忠实一块碑是这个项目的卖点；
> ② **编辑时明示，成品时干净**：屏幕上借来的字套朱砂虚线框，
> 导出的 PNG **一律不画红框**（成品要能拿去展示），诚实性靠落款那句
> 「其中 N 字借自《颜勤礼碑》」。

## 七、出错了怎么办

| 你看到的 | 意思 | 怎么办 |
| --- | --- | --- |
| `[ERROR] Python environment is not ready` | 隔离环境的 Python 找不到了 | 找长庚 |
| `[停] data/inbox 里没有页图` | 投递箱是空的 | 把截图放进去再双击 |
| `[停] 找不到页图：04.png` | `data/processed/` 里没这个文件 | 检查文件名是不是 `04.png` |
| `ModuleNotFoundError: PIL` | 用错 Python 了 | 别双击 `.py`，双击 `.bat` |
| 卡片条数比上次少很多 | 可能某页被重切坏了 | 去 `glyphs_XX/_stale/` 翻旧结果 |
| 组员填的字没进库 | 核对人没签 / 放了 xlsx / 放错文件夹 | 看收卡输出里的「未签字 N 条」 |
| 网页上字是黑方块 | 翻墨那步没跑 | 重跑 `一键_收卡片.bat` |
| 导出 PNG 上落款被印章压住 | 老版本的毛病 | 已修（10-28）：印章排在落款下方，纸不够高会自动接长 |

**万一切坏了别慌**：`强制重切.bat` 每次都会把旧结果先挪到 `glyphs_XX/_stale/时间戳/`，
从不直接删。想找回哪个文件，从那儿拷回来就行。

## 八、想学命令行（可选）

`.bat` 背后就是这几条，在项目根目录下：

```bash

# 收卡片
python tools/pipeline_in.py

# 查缺口 / 分组
```

## 九、这套东西为什么这么设计（给你讲透，汇报时可能用得上）

**为什么不干脆做个网页上传图片、一键切字？**
能做，但要服务器、要上传、要处理跨域。我们 11/05 就要汇报，把工程量花在演示效果上更划算。
切字是**组会时在你自己电脑上跑一次**的事，不需要做成产品功能。

**为什么卡片用 csv 而不是在线表格？**
csv 是纯文本：能进 git、能版本对比、程序零误差读回来、Excel 双击就能填。
在线表格要联网、要权限、导出格式还容易变。

**为什么切完还要"人工核对"这一道？**
拓本字口模糊，机器只能定位"这里有个字"，认不出"这是什么字"。
而且**认错字是硬伤**——汇报时老师指着一个错字问"这是颜体的'德'吗"，
比留个空格难看得多。所以我们的红线是：**库里有就必须有出处、有核对人、有状态。**

**为什么"存疑"要单独一个状态？**
因为我们不确定的东西要**敢说不确定**。网页上会显示黄色角标，
老师问起来你能坦然说"这个字风化严重，我们标了存疑"——这是加分项，不是扣分项。

**为什么收卡只认 `回收/` 一个文件夹？**
因为"扫整个目录"听起来方便，实际是把判断权交给了程序：
它分不清哪张是发出去的、哪张是三周前的抽样件。**宁可多一步手工，也不要脏数据进库**——
数据脏了要回滚到 meta 那一层，代价大得多。
